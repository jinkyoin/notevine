# 시트 블록 설계 (노트 안에서 입력하면 합계가 자동으로 나오는 그리드)

작성일 2026-11-25 · 규모: 프로젝트 · 상태: 초안(빌더 확인 반영, 사용자 승인 전)

## 1. 목적과 이유

사용자가 노트 안에서 견적서·예산표 같은 금액 표를 엑셀처럼 칸에 바로 입력하고, 합계를 직접 계산하지 않고 자동으로 보고 싶어 한다.
지금은 `| 항목 | 금액 |` 표를 글자로 쓰고, 읽기 모드에서만 표로 그려진다. 합계는 손으로 계산해야 한다.

- 사용자가 한 말: "그리드에 금액을 입력하면 자동으로 합계를 보여주는 정도의 기능". 엑셀 전체를 흉내 내는 것은 원하지 않는다.
- 사용자가 고른 방향: 노트 안의 ` ```sheet ` 블록(방법 1). 폴더 표 보기의 합계(C)와 기존 마크다운 표를 그리드로 바꾸는 것(방법 2)은 하지 않는다.

## 2. 목표 / 비목표 / 반대 목표

**목표**
- 노트에 ` ```sheet ` 블록을 넣으면, 커서가 블록 밖에 있을 때 편집 가능한 그리드로 보인다.
- 칸을 누르고 입력하면 맨 아래 합계 줄이 바로 갱신된다.
- 칸에 `=B2*C2`처럼 사칙연산(+ − × ÷, 괄호)과 다른 칸 참조를 쓸 수 있고, 칸에는 계산 결과가 보인다.
- 읽기 모드에서도 같은 표와 합계가 읽기 전용으로 보인다.
- 명령 팔레트에서 시트 블록을 넣을 수 있다.

**비목표**
- 함수(`SUM` 등), 범위 참조(`B2:B5`), 다른 시트·노트 참조, 수식 복사(채우기), 엑셀 파일(.xlsx) 가져오기·내보내기, 칸 서식·병합·열 너비 저장, 정렬. (사칙연산과 칸 참조는 목표다.)
- 기존 마크다운 표(`| a | b |`)를 그리드로 바꾸기.
- 폴더 표 보기의 합계.

**반대 목표(기술적으로 동작해도 실패로 보는 것)**
- 사용자가 고치지 않은 블록의 글자가 바뀌는 것. 그리드는 보기만 해서는 노트를 다시 쓰지 않는다.
- 한글 입력(IME) 조합 중에 글자가 끊기거나 사라지는 것.
- 블록이 깨졌을 때 내용이 사라지는 것(깨진 블록은 일반 코드 블록처럼 글자로 보여 준다).

## 3. 제약

- 노트를 잃으면 안 된다. 저장 글자를 바꾸는 코드에는 테스트를 함께 둔다(CLAUDE.md).
- 한글 IME 조합 중에는 단축키·자동완성·되돌려 쓰기를 보류한다.
- 화면 글은 `tx("…")`로 감싸고 `src/i18n/en.json`에 영어를 추가한다.
- 명령은 `src/appCommands.ts`·`src/commands.ts`에 등록한다.
- 네트워크 접속 없음. 새 라이브러리 없이 CodeMirror 위젯과 기존 `marked` 렌더러로 만든다.
- 읽기 모드 글은 기존 정화(DOMPurify)를 거친다. 칸 글자는 모두 이스케이프한다.

## 4. 접근 방식 (고려한 것과 선택)

| | 내용 | 장단점 |
|---|---|---|
| **1. ` ```sheet ` 블록 (선택)** | 새 블록 문법. 에디터 위젯 + 읽기 모드 렌더 | 기존 노트에 영향 없음, 합계 규칙을 블록 안에서 정할 수 있음. 기존 표는 그리드가 되지 않음 |
| 2. 기존 마크다운 표를 그리드로 | 표 글자를 위젯이 다시 씀 | 웹 클립·AI 표도 대상이지만, 칸 안의 `\|`·서식이 깨질 위험이 커서 탈락 |
| 3. C. 폴더 표 보기 합계 | 속성 열 합계 | 노트 한 장 안의 견적표용이 아니라서 탈락 |

사용자가 방법 1을 골랐다.

## 5. 설계

### 5.1 저장 형식

````
```sheet
항목 | 수량 | 단가
인건비 | 3 | 1200000
장비 | 2 | 500000
```
````

- 줄 하나가 행, ` | `로 칸을 가른다. 첫 줄은 제목 행이다. 양 끝의 `|`는 있어도 없어도 읽는다.
- 칸 안의 `|`는 `\|`로 쓴다. 칸 글자 앞뒤 공백은 저장할 때 한 칸으로 맞춘다.
- 합계 줄은 저장하지 않고 항상 계산해서 보여 준다. (다른 마크다운 프로그램에서는 합계가 안 보인다 — 알려진 한계.)
- 수식은 `=`로 시작하는 칸 글자를 그대로 저장한다(예: `=B2*C2`). 결과는 저장하지 않고 항상 계산한다.
- 줄마다 칸 수가 달라도 읽을 수 있다(모자란 칸은 빈 칸으로 본다). 사용자가 고치기 전에는 원문 그대로 둔다.

### 5.2 합계 규칙 (내가 정한 것)

- **첫 열은 이름 열이다.** 합계를 내지 않고, 합계 줄의 첫 칸에 "합계"를 표시한다. (번호 열이 있어도 합치지 않는다. *빌더 확인 후 내가 정한 것*)
- 숫자 열: 둘째 열부터, 제목 행을 뺀 칸 중 비어 있지 않은 칸이 **하나 이상이고 모두** 숫자인 열. 숫자는 `1,200,000`, `-500`, `3.5`, `1200000원`처럼 쉼표·`원` 접미를 허용한다. 데이터 칸이 모두 비어 있는 열은 합계를 내지 않는다(0으로 보이지 않게).
- 숫자 열이 하나도 없으면 합계 줄을 만들지 않는다.
- 합계는 천 단위 쉼표를 붙여 보여 준다. 소수는 입력된 최대 자릿수까지 보인다.
- 합계 계산과 수식 계산은 순수 함수로 두고 에디터와 읽기 모드가 같이 쓴다.

### 5.2-1 수식 규칙 (내가 정한 것)

- `=`로 시작하는 칸이 수식이다. 쓸 수 있는 것: 숫자(쉼표·소수 허용), 칸 참조, `+` `-` `*` `/`, 괄호, 앞의 `-`(음수). 곱셈·나눗셈이 덧셈·뺄셈보다 먼저다. `×`·`÷`도 입력받아 `*`·`/`로 읽는다.
- 칸 참조는 엑셀처럼 **열 글자 + 행 번호**(`B2`)다. 제목 행이 1행이고 데이터는 2행부터이다. 그리드 가장자리에 열 글자(A, B, C…)와 행 번호를 작게 보여 주어 참조를 알 수 있게 한다.
- 참조한 칸이 숫자이거나 숫자로 읽히는 글자(`1,200`, `1200원`)이면 그 값을 쓴다. 비어 있으면 0이다. 글자이면 오류다.
- 오류는 칸에 `#오류`(문법), `#나누기0`, `#참조`(없는 칸), `#순환`(자기 자신을 거쳐 돌아옴), `#글자`(숫자가 아닌 칸을 참조)로 칸에 보인다. 오류 칸이 있는 열은 합이 틀려 보이지 않도록 합계 칸에도 `#오류`를 보인다(합계에 일부만 더하지 않는다).
- 계산은 직접 만든 작은 파서로 한다(`eval`·`Function` 금지). 계산 순서는 칸 참조를 따라 재귀하고, 방문 중인 칸 집합으로 순환을 잡는다.
- 합계 줄: 수식 칸은 **계산된 값**으로 숫자 열 판정과 합계에 쓴다. 합계 줄에는 수식을 쓰지 않는다. (합계 줄은 저장되지 않으므로 참조할 수 없다.)
- 행·열을 넣거나 지워도 다른 칸의 수식 참조는 자동으로 고치지 않는다(빌더가 판단하지 않고 비목표). 대신 행·열 삭제 단추에 "수식이 있는 칸의 참조가 어긋날 수 있다"고 알린다.
- 그리드에서 수식 칸을 누르면 수식이 보이고, 칸을 벗어나면 결과가 보인다.

### 5.3 에디터 (CodeMirror)

- `frontmatterFold.ts`와 같은 방식: 블록 위젯(`Decoration.replace({block:true})`)으로 ` ```sheet ` ~ ` ``` ` 전체를 그리드로 바꾼다. 커서가 블록 안에 들어가면(위젯 옆에서 방향키, 위젯의 "원문 편집" 단추) 위젯을 걷고 글자를 그대로 편집한다.
- 그리드 칸은 입력 칸이다. 입력하는 동안 합계 줄은 화면에서만 실시간 갱신한다. **문서에 쓰는 때는 칸을 벗어날 때(Enter·Tab·blur)다.** 한글 조합 중(`compositionstart`~`compositionend`)에는 문서에 쓰지 않는다.
- 문서에 쓸 때는 블록 범위만 `view.dispatch`로 바꾼다. 일반 변경이라 Ctrl+Z로 되돌릴 수 있다.
- 행·열 추가·삭제는 위젯의 작은 단추(행 아래 `+`, 행·열 `×`)로 한다. Tab은 다음 칸, 마지막 칸의 Enter/Tab은 새 행.
- 글자가 하나도 없는 빈 블록만 위젯을 만들지 않고 원문으로 둔다. 그 밖의 블록은 모두 그리드로 읽는다(`|`가 없는 줄은 한 칸짜리 행). 읽는 것만으로는 글자를 잃지 않으므로 별도의 "깨진 블록" 판정은 두지 않는다. 그리드는 내용이 실제로 바뀐 때만 문서에 쓴다(칸에 들어갔다 나오기만 하면 쓰지 않는다).
- 맨 바깥(목록·인용 안이 아닌) ` ``` ` 블록만 에디터 위젯 대상이다. `~~~`·네 개 이상의 백틱 울타리는 일반 코드 블록으로 둔다. 읽기 모드는 `marked`가 넘겨 주는 `sheet` 코드 블록이면 어디서든 그린다.

### 5.4 읽기 모드

- `renderNote.ts`의 `code` 렌더러에 `sheet`를 추가해 읽기 전용 `<table class="sheet-block">`과 합계 줄을 낸다. 모든 글자는 `esc`를 거친다.
- 숫자 열은 오른쪽 정렬.

### 5.5 넣는 방법

- 명령 팔레트 "시트(합계 표) 넣기": 커서 위치에 제목 행 + 빈 행 2개짜리 블록을 넣고 첫 칸으로 간다.
- 도움말(`MarkdownHelp.tsx`)과 사용자 매뉴얼에 문법·합계 규칙을 적는다.

### 5.7 테스트

- 파싱·저장: 왕복 후 글자 동일, `\|` 이스케이프, 양 끝 `|`, 빈 칸, 칸 수가 다른 행, 한글 칸, 빈 블록.
- 수식: 우선순위, 괄호, 음수, 소수, `×÷`, 0 나누기, 없는 칸 참조, 순환 참조(`A→B→A`, 자기 자신), 빈 칸은 0, 글자 칸 참조 오류, 수식 칸이 합계에 들어가는지, 오류 칸이 합계에서 빠지는지, 부동소수 오차(0.1+0.2), 악의적인 글자(`=alert(1)`, 아주 긴 식, 깊은 괄호)가 안전하게 오류가 되는지.
- 합계: 쉼표·원 접미·음수·소수, 숫자와 글자가 섞인 열은 합계 제외, 숫자 열이 없으면 합계 줄 없음, 큰 수 부동소수 오차.
- 읽기 모드 HTML: 합계 줄, 이스케이프(`<script>` 같은 칸 글자).
- 보기만 해서는 문서가 바뀌지 않음(위젯 단위 테스트가 가능하면 포함).

## 6. 빌더에게 맡기는 것

- 위젯 안의 키 입력·포커스 처리 세부, 단추 모양, CSS.
- 요구사항 ID(FR-) 번호와 화면설계서 SCR 번호 부여.
- 큰 시트(수백 행)에서의 성능 대응 필요 여부.
- 버전 번호는 올리지 않는다(사용자가 요청할 때만).
