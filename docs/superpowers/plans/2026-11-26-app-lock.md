# PC 앱 잠금 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 자리를 비운 사이 다른 사람이 노트를 보지 못하게 하는 PC 앱 잠금(없음 / Windows Hello / 비밀번호)을 넣고, 저장에 실패한 채 앱이 끝나 편집을 잃는 문제를 고친다.

**Architecture:** 잠금 상태·비밀번호·잠금 계기 감지는 Rust(`src-tauri/src/lock/`)가 갖고 `lock-changed` 이벤트로 화면에 알린다. 화면(`src/lock/`)은 아래 UI를 그대로 둔 채 불투명한 잠금 화면으로 덮고 키 입력을 막는다. 저장 실패는 `flushEditor`가 `false`로 알리고 종료 경로가 이를 확인한다.

**Tech Stack:** Tauri 2.12, Rust 2024, `argon2` 0.5, `windows` 0.62, React 19 + zustand, vitest(jsdom)

**Spec:** `docs/superpowers/specs/2026-11-26-app-lock-design.md`

## Global Constraints

- **커밋·푸시는 사용자가 요청할 때만 한다.** 각 작업 끝은 "확인"이며 커밋 단계가 없다. 커밋을 요청받으면 `main`에서 새 브랜치를 먼저 만든다.
- 이번 작업과 무관한 수정(`src/editor/livePreview.ts`, `docs/작업기록.md`)과 untracked 파일은 건드리지 않는다.
- 화면 글은 한국어 `tx("…")`, 같은 키를 `src/i18n/en.json`에 영어로 추가한다. 트레이 메뉴 등 Rust 문구는 기존 관례대로 한국어.
- Tauri 명령 이름·인자는 Rust와 `src/api.ts`가 일치해야 한다.
- 화면 컴포넌트 주석에 `SCR-30`, 요구사항 `NFR-SEC-04`를 적는다.
- 네트워크 접속을 추가하지 않는다. 버전 번호를 올리지 않는다. 안드로이드 저장소는 읽기만 한다.
- 설정 파일은 앱 설정 폴더의 `app-lock.json`(개발용 빌드는 `.dev` 폴더). 비밀번호는 Argon2id 해시만 저장한다.
- 값: 비밀번호 4자(글자 수) 이상 · 연속 5번 틀리면 30초 대기 · 입력 없음 1/**5**/10/30분/0(사용 안 함) · 숨김·최소화 30초 · 지금 잠그기 `Ctrl+Alt+L`.
- `cargo clippy --all-targets -- -D warnings` 경고 0개.

```rust
#[serde(rename_all = "lowercase")] pub enum Mode { Off, Hello, Password, Broken }
#[serde(rename_all = "lowercase")] pub enum Reason { Start, Manual, Idle, Hidden, Session, Sleep }
pub struct Status { pub mode: Mode, pub locked: bool, pub reason: Option<Reason>, pub epoch: u64, pub away: bool, pub idle_minutes: u32 }
pub enum Check { Ok, Wrong, Wait(u32) }
#[serde(rename_all = "lowercase")] pub enum HelloOutcome { Ok, Cancelled, Unavailable, Failed }
pub trait Hello { fn verify(&self, message: &str) -> HelloOutcome; }
pub struct Change { pub mode: Option<Mode>, pub password: Option<String>, pub idle_minutes: Option<u32> } // Deserialize
#[serde(tag = "status", rename_all = "lowercase")]
pub enum ChangeOutcome { Ok, Wrong, Wait { seconds: u32 }, Cancelled, Unavailable, Failed }

impl AppLock {
  pub fn load(config_dir: &Path) -> Self;                       // mode != Off 이면 locked, reason Start
  pub fn status(&self) -> Status;
  pub fn lock(&self, reason: Reason) -> bool;                   // 상태가 바뀌면 true
  pub fn set_away(&self, away: bool) -> bool;
  pub fn unlock_password(&self, password: &str, now: u64) -> Check;   // now: UNIX 초
  pub fn unlock_hello(&self, outcome: HelloOutcome) -> HelloOutcome;  // Hello 방식 + Ok 일 때만 풂
  pub fn change(&self, change: Change, proof: Option<&str>, message: &str, hello: &dyn Hello, now: u64) -> AppResult<ChangeOutcome>;
  pub fn idle_limit(&self) -> Option<Duration>;                 // 0 → None
}
```

규칙: 설정 파일 `{mode, hash, idle_minutes, fails, wait_until}`. 파일 없음 → Off/5. 읽기·해석 실패, 모르는 mode, 해시가 없거나 해석 불가인 password → Broken(어떤 방법으로도 안 풀리고 변경도 거부). 모르는 `idle_minutes` → 5. `lock`: Off면 false, 풀려 있으면 잠그고 `epoch += 1`, 이미 잠겨 있으면 Hidden·Session·Sleep일 때만 이유를 바꾸고 `epoch += 1`. `change`: 잠긴 동안은 오류. 지금 방식이 password면 `proof`를 `unlock_password`와 같은 실패 횟수로 검사, 지금이나 새 방식이 hello면 `hello.verify`를 한 번만 부름. password로 바꾸려면 새 비밀번호 필수, 4자 미만이면 `AppError::System("4자 이상으로 정하세요")`. 저장에 실패하면 메모리 상태도 바꾸지 않는다. Hello를 부르는 동안 내부 Mutex를 잡지 않는다.
